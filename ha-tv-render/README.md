# ha-tv-render — панель Home Assistant на мониторе видеорегистратора

Показывает лёгкую HTML-панель Home Assistant (`ha-home74/www/tv.html`) на мониторе регистратора **XM/Partizan (NETIP, порт 34567)** как канал IP-камеры, не нагружая слабый HA-хост. Всё крутится на отдельной Armbian-приставке (aarch64, 4 ядра).

```
HA (/local/tv.html) ──► renderer (Chromium kiosk + Xvfb + ffmpeg x11grab, H.264 baseline 1280×720/3 fps)
                          └─► mediamtx (RTSP :8554, /tv)
                                └─► dvrip (свой NETIP-сервер, :34567) ──► регистратор (канал «камера»)
```

| Сервис | Что делает |
|---|---|
| `renderer/` | Chromium открывает `HA_URL + DASH_PATH`, логинится отдельным **не-админским** пользователем HA (OAuth, токен обновляется каждые 20 мин без перезагрузки страницы), ffmpeg публикует RTSP. Авто-перезапуск ffmpeg/chromium. `siren.py` — звуковой сигнал при тревоге. |
| `mediamtx/` | RTSP-сервер. Чтение из LAN без пароля, публикация только из контейнеров. |
| `dvrip/` | Эмулятор NETIP-камеры: отдаёт регистратору поток из RTSP. `canned.json` — ответы настоящей XM-камеры (серийный номер заменён нулями). |

## Запуск
1. В HA создайте отдельного пользователя `tv` (не администратор, «только локальный доступ»).
2. `cp .env.example .env` и впишите `HA_PASS` (файл `.env` в git не попадает).
3. `docker compose up -d --build`
4. На регистраторе добавьте канал: протокол **NETIP**, IP приставки, порт `34567`, логин `admin`, любой пароль (сервер пароль не проверяет).
5. Проверка потока: `rtsp://<IP приставки>:8554/tv`.

Каталог `data/` (профиль Chromium с токенами) создаётся на хосте и **не должен** попадать в репозиторий (см. `.gitignore`).

## Что оказалось критичным (выяснено перехватом обмена регистратор↔камера)
1. Регистратор открывает **два соединения**: медиа (шлёт только `OPMonitor Claim`) и control (Login, `OPMonitor Start`, запросы конфигурации, keep-alive). Поток надо стартовать по `Claim` в том же сокете, на `Start` отвечать без потока.
2. Ответы конфигурации (`Simplify.Encode`, `SystemFunction`, `SystemInfo`, `EncodeCapability`, …) — реальные, из `canned.json`; JSON с пробелами `{ "K" : v }`.
3. `seq` в медиа-пакетах растёт попакетно (каждые 8192 Б), старт с 0.
4. H.264: у P-кадров `nal_ref_idc=3` (байт `0x61`), на ключевой кадр добавляется XM SEI; байт профиля SPS правится.
5. Один поток 720p на оба типа потока; отдельный суб-поток ломает канал.
6. Медиа-соединение **не закрывать по таймауту чтения** (регистратор на нём только слушает).

Проверено на прошивке регистратора `V4.02.R12`. ONVIF-путь (эмулятор для Unifi) оказался неработоспособным с XM и не включён.
